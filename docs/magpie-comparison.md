# Comparison with magpie

hofund is an independent reimplementation. This table records, per subsystem,
what [magpie](https://github.com/yetone/magpie) does, whether hofund adopts
that behavior or redesigns it, and why. It is a design record, not a porting
guide. hofund does not copy magpie source. The MIT notice lives in
`THIRD_PARTY_NOTICES.md`.

"Adopt" means the outward behavior is worth keeping and is reimplemented
against hofund's crates. "Redesign" means the magpie shape is unsound for
this codebase and hofund does something else on purpose.

Update this table in the same change that adds or changes a subsystem.

## P1

| Subsystem | magpie approach | Verdict | hofund approach | Rationale |
| --- | --- | --- | --- | --- |
| Responses codec | One in-memory request shape shared by Chat Completions, Messages, Responses, and Gemini. `parseResponses` / `buildResponses` speak that shape. A Responses turn is split into items (`message`, `function_call`, `function_call_output`, `reasoning`) and merged back into consecutive same-role messages. Sealed reasoning (`encrypted_content`, with id and summary) is stored and written back byte-faithful. Plain reasoning text is replayed only for models that require it. `instructions` is the system prompt. `allowed_tools` filters the tool list. Argument deltas are reconciled with `function_call_arguments.done` so a finished call is not doubled. A failed response or an `error` event is a failure, not a completed reply. Orphaned tool calls get a synthetic output before the upstream sees them (`pairToolItems`). `store` defaults to false. | Adopt | `OpenAiResponses` in `hofund-codec` translates only to `hofund-ir`. Consecutive assistant items merge into one message. Sealed reasoning on a request or a response body is kept on the thinking part and written back as the original item. A stream copies non-empty `encrypted_content` onto the thinking part and the encoder writes that item back. Unsealed reasoning text is encoded as `reasoning_text`; a quirk profile may strip it before encode. `instructions` round-trips as a leading plain system message. `allowed_tools` narrows tools. The done-event arguments extend the streamed prefix instead of appending a second copy. `response.failed` and `error` stay visible to the caller. A `response.failed` frame that arrives before the turn starts, and whose output is empty, stays an unknown event so the provider can treat it as a failure. After `response.created`, the same frame is a stop reason. The Responses adapter, not the codec, repairs orphaned tool outputs and sets `store: false` when the client did not set `store`. | The hub-and-spoke translation, the item split, sealed-reasoning passthrough, and the stream edge cases are the behavior clients already depend on. `function`, `custom`, `namespace`, `web_search`, and client `tool_search` are accepted. Same-protocol encode writes the original `tools` array back. Crossing protocols flattens a namespace to `namespace__name`, offers a custom tool as a function with one string `input`, offers client `tool_search` as a function, and drops `web_search` and any other type with a warning instead of a 400. An unknown input item is preserved rather than dropped. Synthetic tool outputs and `store: false` are adapter policy, so a codec round trip stays faithful to the IR. |
| Providers | A very large `Provider` struct (endpoints, keys, accounts, quotas, headers, and product flags together) plus per-vendor files under the gateway as well as under `provider`. HTTP is a shared client. Streaming is decoded into the internal event type. | Redesign | A small `Provider` trait: an id and `execute(request) ->` unary response or a pull-based stream of IR events. Two adapters, `openai_compat` (Chat or Responses, configurable base URL and headers) and `anthropic` (Messages). `reqwest` with rustls. Quirk profiles are applied to the IR before encode. Upstream HTTP failures become a typed error (connect, timeout, transport, interrupted, status, decode) with the status code and a message. A body failure or timeout after a 2xx status is `Interrupted`, distinct from a pre-send `Connect`; same-member retry of that failure requires an idempotent call. A non-2xx body-read failure still returns the original `Status` and `Retry-After`, using empty bytes when the body cannot be read. A leading stream event named `error` or `response.failed`, or a chat chunk that is only an error object, becomes status 502 before any event is yielded. A stream is a `Stream` the caller polls, so a slow client slows the upstream read. | The god-struct and the vendor branches inside the gateway are the shape this repository exists to avoid. The trait boundary is what the router and the tests can stand on. Protocol differences stay in the codec the adapter holds. |
| Provider preset fragments | Go literals declare flat endpoint fields and ordered regions; credentials are derived rather than stored on each row. | Adopt with stricter data validation | TOML fragments keep catalog key names, flat wires, aliases, and declared region order, compile to static data, and use catalog-equivalent selection and credential derivation. Unknown keys fail the build, unknown-region errors list valid ids, and `generative` is a hofund extension. There is no `credential` key. | Rows move without rewriting or duplicating endpoint capabilities in a protocol list. Compile-time validation catches migration typos while preserving current endpoint behavior. |
| Quirks | Real vendor exceptions are encoded as host and model checks scattered through gateway translation (`rejectTemp`, reasoning replay, optional-field retry, per-vendor envelopes). The knowledge is valuable; the location is not. | Redesign | `hofund-quirks` is data: named profiles of rules (`omit temperature`, `omit top_p`, `default max tokens`, `omit unsealed reasoning`, `fold developer into system`). Providers apply a profile by id. Gateway and router never see a profile. | The exceptions are real. Putting them behind a profile id keeps them testable and keeps vendor names out of the gateway and the router. Profiles shipped here are the small set P1 needs, not a catalog of every upstream. |
| Routing and failover | Several strategies (ordered, rotate, least-used, smart, pace) over accounts, plus a fallback list. A failed upstream is not retried once any reply byte has been sent. Connect failures, 408, 429, 5xx, and a large set of body-word heuristics are retryable. A failed candidate rests for a while so the next request does not hammer it. Global counters back some strategies. A new rest overwrites the old deadline, and credit uses a fixed 30-minute rest. | Adopt the pre-byte failover rule. Redesign the rest. | `hofund-router` maps a model name to an ordered list of providers. It fails over only while it has not yet yielded a stream event, and only for connect, timeout, or interrupted-body errors under `connect_errors` and for a configurable set of HTTP statuses. The default set is 429, 500, 502, 503, and 504. 400 does not fail over. `hofund_router::Cooldowns` keeps explicit rest timers and ladders keyed by `MemberId`; the daemon shares that book across router snapshots. Ready members go first, followed by one soonest cooling probe. Non-positive header hints are absent and positive hints cap at one hour for every failure cause. Only exhausted passive observations rest, using resets capped at eight days. Unlike magpie, a new event never shortens an active rest, and credit honors a longer capped header hint above 30 minutes. There is no process-global route counter. | Ordered failover before the client sees a byte is the property agents need. The rest timer is explicit router state keyed by member id, not a global, and survives replacement of the member instances. Keeping the longer rest prevents a short hint from cutting a long quota rest; the credit rule respects a longer vendor hint. Quota-aware strategies and the word heuristics still need account state this version does not have. |
| Gateway server | One `serve` method, thousands of lines, on a server type that also owns sessions, tools, redaction, and vendor-specific rewrites. Routes for Chat, Responses, Messages, and Gemini live beside that logic. | Redesign | `hofund-gateway` is an axum process edge. It authenticates, picks the inbound `Codec` it was given, asks the router, and writes the encoded body or a pull-based SSE body. It does not name vendors. Default bind is `127.0.0.1:3425`. | The request path should be readable as: decode, route, encode. Vendor adjustments stay below the router. Binding to loopback by default matches a local gateway; a configured address may be wider, and authentication still applies. |
| Auth | Loopback clients may omit a key. Other machines need a gateway key, compared in constant time, after an allow-list and a DNS-rebinding check. Many keys, with budgets. | Adopt constant-time compare. Redesign the policy. | One bearer token, created on first run, stored in a file mode `0600` (on Unix), rotated by replacing a temporary file. Every routed request must send it, including from loopback. Generative Language routes also accept `x-goog-api-key` or a `key` query value. Each presented secret is compared in constant time. | A local gateway with a single token is the P1 threat model. Requiring the token on loopback also closes the rebinding hole magpie closes with a hostname check. The extra header is the one the Generative Language client sends when it is given an API key. Multiple keys and budgets are later. |
| Config | A large settings store, rewritten in place by the agent-integration code, with care taken so a crash does not leave a truncated file. | Adopt atomic replace where this version writes. Redesign the schema. | TOML via `toml_edit`, validated into a small struct: listen address, providers, model routes, failover statuses, token file, usage file. `config check` reports the first structural error. This version does not reload a running process. Coding-agent files are rewritten by `hofund-agent`, recorded in the P2 section. | P1 needs a file a human can read and a checker with a clear error. Hot reload and agent config rewriting are separate subsystems; they are recorded here so they are not forgotten and are not left as comments in code. |
| Usage | A JSONL ledger of rich rows (agent, cache, cost, session, effort), with caches and summaries beside it. Gateway calls and client-reported calls share it. | Redesign | SQLite (`rusqlite`, bundled) with one row per gateway request: model, upstream id, input tokens, output tokens, latency, status, time. `hofund usage` prints that table. Cache counters stay on the IR usage object and are not subtracted from input tokens. | The ledger's product surface is much larger than P1. A single table is enough to see where traffic went. Keeping protocol totals intact avoids inventing a billing split. |
| CLI | A large command tree (accounts, groups, serve, usage, plugins, diagnostics) built around the process. | Redesign | `hofund serve`, `hofund config check`, `hofund token show`, `hofund token rotate`, `hofund usage`, plus `hofund agent list`, `hofund agent connect`, `hofund agent disconnect`, and `hofund agent status`. The binary parses arguments and calls the daemon or `hofund-agent`. It does not route and it does not encode protocols. | These are the commands that exercise the local process. The rest of magpie's CLI belongs to later subsystems. |

## P2

| Subsystem | magpie approach | Verdict | hofund approach | Rationale |
| --- | --- | --- | --- | --- |
| Agent adapter shape | `Agent` is a large struct of closures (`Field.Get` / `Field.Set`, `Unwire`, `Sync`, `Join`, `Restore`) built inline per product. Path helpers and provider JSON live beside those closures. | Redesign | `AgentAdapter` is a small trait: detect, read, plan, apply, revert, status. Each agent is a static description of files and keys (`Origin`, `V1`, `Token`, or a literal). `Session` carries the home directory and the documented env overrides. `GatewayTarget` is the base URL and token, passed in by the daemon. | Closures hide the edit and make the backup rule hard to test. A description is data: the same apply path serves every agent, and a test can plant fixtures in a temp directory. |
| Agent descriptions | A Go plugin `Desc` carries `Config`, `Format`, `Model`, and `Prefix`; the host writes every key and stashes prior values. | Adopt with redesign | Build-time `agent.toml` becomes a static `AgentDescription` with per-OS path templates and typed slots. The shared engine stashes values per key, and the agent kit checks committed golden cases on every OS. Catalog composition returns an error when a built-in has no compiled description instead of silently dropping it. | Declarative data covers ordinary agents without a crate per product. Compile-time validation avoids runtime parsing, per-key history preserves user edits, and shared goldens and shipped-plugin regressions lock the resulting files and lifecycle. |
| Agent path overrides | At `cbbf316`, `appdir/codex.go:25`, `appdir/claude.go:25`, `appdir/env.go:27-32,81-93,95-113`, `agentenv/agentenv.go:32,40`, and `agent/agents.go:81` accept only usable rooted values for these path variables. | Adopt | `Session` constructors, named setters, and compiled resolution share one filter: empty and relative overrides read as unset, while raw environment values remain available. | Empty and relative overrides read as unset in the reference. One filter keeps every shipped adapter on the same default paths. |
| Safe file rewrite | Before a change, the original bytes are copied to a sibling `*.before-magpie`. A missing file is recorded so restore can delete it. The write itself is an atomic replace. Unrelated keys are preserved. | Adopt the safety rules. Redesign the marker names. | The first apply copies an existing file to `*.hofund.bak`, or writes an empty `*.hofund.absent` when the file is new. A later apply does not overwrite that backup. The new bytes go to a sibling temporary file and are renamed into place (on Windows, replace falls back to remove-then-rename when the destination exists). Revert writes the backup back, or deletes the file, and removes the marker. TOML is edited with `toml_edit`, so comments and unrelated keys stay. JSON and JSONC keep unrelated values; comments in JSON are dropped until revert. Env files keep comments, blank lines, `export` prefixes, and unrelated keys. Apply is idempotent. `plan` prints a line diff and writes nothing. | Those are the properties that make a config edit safe to undo. The marker suffix is hofund's, so a checkout that also has the other project's backups does not collide with them. JSON key order follows the `serde_json` map; values are what the tests lock. |
| Claude Code | `~/.claude/settings.json`, with `env.ANTHROPIC_BASE_URL` and `env.ANTHROPIC_AUTH_TOKEN`. The directory can be overridden. | Adopt | Same file and the same two keys. `CLAUDE_CONFIG_DIR` replaces `~/.claude` (on Windows, `%USERPROFILE%\.claude`). The base URL is the gateway origin with no `/v1`, because the client appends `/v1/messages`. The model is not rewritten. | This is the documented gateway hook. Checked against the Claude Code settings, gateway, and env-var docs. |
| Codex CLI | `~/.codex/config.toml`. A custom provider table sets `base_url`, `wire_api = "responses"`, and `experimental_bearer_token`. `model_provider` selects it. | Adopt | Provider id `hofund` (the ids `openai`, `ollama`, and `lmstudio` are reserved). `base_url` is the origin plus `/v1`. `wire_api` is `responses`. The bearer field is `experimental_bearer_token`, without `env_key` or `requires_openai_auth`. `CODEX_HOME` replaces `~/.codex`. The user's `model` key stays. | Codex posts `{base_url}/responses`. The token lives in hofund's token file, not in the shell, so the documented bearer field is the one that connects without a second export. Checked against the Codex config reference. |
| Gemini CLI | `~/.gemini/settings.json` `security.auth.selectedType`, plus `~/.gemini/.env` with `GOOGLE_GEMINI_BASE_URL` and `GEMINI_API_KEY`. The writer always uses the user home (`internal/agent/gemini.go:28-31`), although trace discovery honors `GEMINI_CLI_HOME` (`internal/sessions/traces_gemini.go:17-22`) and the environment list calls it the session/config home (`internal/agentenv/agentenv.go:39-40`). | Adopt the files. Redesign the auth type. Deliberately diverge on the home override. | Settings `security.auth.selectedType` is `gemini-api-key`. `.env` sets `GEMINI_API_KEY`, `GOOGLE_GEMINI_BASE_URL` to the origin, and `GEMINI_API_KEY_AUTH_MECHANISM=bearer`. An absolute `GEMINI_CLI_HOME` is the parent of `.gemini` for both files; empty and relative values fall back to the user home. The gateway serves `generateContent` and `streamGenerateContent` for that origin. | Gemini CLI's `homedir()` (`packages/core/src/utils/paths.ts`) returns `GEMINI_CLI_HOME` when set, and `getGlobalGeminiDir` (`packages/core/src/config/storage.ts`) joins that home with `.gemini`, so writing the user home instead would leave an overridden CLI unconnected. The public docs name the files. `GEMINI_API_KEY_AUTH_MECHANISM` is real in `contentGenerator.ts` (default `x-goog-api-key`; `bearer` adds `Authorization: Bearer` only for `gemini-api-key` and `vertex-ai`). It is not on the public configuration page. `getAuthTypeFromEnv` returns `gateway` when the base URL is set, and that auth type does not add the bearer header. Non-interactive startup prefers the settings value (`validateNonInterActiveAuth.ts`), so `gemini-api-key` wins, and the base URL is still applied. The SDK also sends `x-goog-api-key`. The gateway accepts either header. |
| OpenCode | The integration writes `provider.<id>` with npm `@ai-sdk/openai-compatible`, `name`, `options.baseURL`, `options.apiKey`, and `models` (`internal/agent/agents.go`, `e57e785`). `models` comes from the catalog (`magpieModels`: name, modalities, context and output limits, reasoning, variants), not from a list of route names. | Adopt the current providers page. Leave `models` empty until a catalog exists. | Global file `~/.config/opencode/opencode.json`, or `opencode.jsonc` when that file already exists. `provider.hofund.npm` is `@ai-sdk/openai-compatible`, `options.baseURL` is the origin plus `/v1`, `options.apiKey` is the token, and `models` is `{}`. No model id is invented. `hofund agent connect opencode` says the catalog is not shipped and that route names are not copied into `models`. The docs use `~/.config` on every platform, so Windows uses that path too. Neither page documents an env var that moves this file. | The current providers page is `provider.<id>.npm` (<https://opencode.ai/docs/providers/>, checked 2026-10-25). The v2 page uses `providers` plus `package` and `settings` (<https://opencode.ai/v2/docs/providers/>). This follows the current page, which is also what magpie writes. JSONC comments are restored only by revert. Copying route names into `models` would not match a catalog entry, which also carries context, modalities, and reasoning. |
| Generative Language codec | `internal/agent/gemini.go` says the CLI only speaks that product's API and that the gateway serves it. The request translation sits inside the large serve path. This checkout has no separate `generateContent` codec. | Adopt the outward behavior. Redesign the location. | `GenerativeLanguage` in `hofund-codec` translates `generateContent` and `streamGenerateContent` (`data:` frames, including `alt=sse`) to the IR: system instruction, function declarations, function calls and responses, thinking parts, thought signatures, and usage metadata. Fields with no IR slot stay on the extension bag. The gateway binds `POST /v1beta/models/{*target}` and looks up the codec with the two method templates. `GET /v1beta/models` lists route models. The model in the path is copied onto the body and wins over a body field. The stream method sets `stream`. Auth accepts a bearer token, `x-goog-api-key`, or a `key` query, each compared in constant time. The upstream adapter is the next row. | A connect that only rewrites the CLI config, without those routes, leaves the CLI unable to complete a turn. The translation belongs in the codec crate. The HTTP router cannot register a dynamic suffix, so the live route is a catch-all and the template strings stay codec-map keys. Vendor names stay out of the gateway. |

## P3

| Subsystem | magpie approach | Verdict | hofund approach | Rationale |
| --- | --- | --- | --- | --- |
| Menu bar | A menu-bar app on macOS, with a window, a TUI, a web UI, and the CLI beside it. The panel shows each agent and the gateway those agents share. The product also updates itself. | Adopt the panel. Redesign the shell. | `hofund-desktop` is a Tauri v2 tray at `apps/desktop`. The tray shows gateway running or stopped, the listen address, one check item per catalog agent, Usage, Open config, and Quit. The window repeats that status, the same agent list, and the usage table. The window starts hidden; closing it hides it and leaves the tray. There is no self-update. | The useful part is one local control surface for the gateway and the agents. A second UI framework, a web UI, and an updater are separate products. The window is a thin page over the same snapshot the tray uses. |
| Tray state | The app process owns a large settings store and reaches into agent integrations directly. Much of that state is process-global. | Redesign | `Control` is a value: a config path, an optional running server, and the last error. Tauri holds it in a mutex on the app state. Commands and menu clicks call `hofund-daemon` (`start`, `stop`, `usage_report`, `local_gateway`) and `hofund-agent` (`apply`, `revert`, `status`). The UI does not match on an agent id. `menu_entries` walks the snapshot, and the snapshot walks `adapters()` in catalog order. | A connect toggle should be the same function the CLI calls. A global and a vendor branch in the window would hide that. Listing the catalog, including an agent whose binary is not installed yet, keeps the menu a projection of the adapter list. |
| Packaging | Release builds are signed and notarized on macOS, and the install script fetches the current build. Checksums ship with the archives. | Adopt checksums and optional signing. Redesign the publisher. | `cargo-dist` 0.32 builds the `hofund` CLI for macOS arm64 and x86_64, Linux x86_64 and aarch64, and Windows x86_64, plus shell and PowerShell installers and SHA-256 checksums. It rejects `universal2-apple-darwin`, so a job in the same workflow runs `lipo` and publishes `hofund-cli-universal2-apple-darwin.tar.gz` with its own `.sha256`. The installers still select one architecture. A second workflow builds the Tauri bundles and writes `SHA256SUMS`. `macos-sign` stays off: an empty GitHub secret is the empty string, which cargo-dist would try to decode, and its codesign invocation has no timestamp. The workflow signs after `dist build` when `CODESIGN_CERTIFICATE`, `CODESIGN_CERTIFICATE_PASSWORD`, and `CODESIGN_IDENTITY` are all set, with `--options runtime --timestamp`, then rewrites that archive and the manifest hash before installers are generated. Notarization (`APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID`) submits a zip copy with `notarytool --wait` and leaves the archive bytes alone. Windows (`WINDOWS_CERTIFICATE`, `WINDOWS_CERTIFICATE_PASSWORD`) runs `signtool` and rewrites the zip checksum the same way. A group with an empty secret is skipped. No tag is pushed by the change that adds the workflow. | The targets and the checksums are what a local install needs. Signing has to be optional in a public repository that does not store certificates. An empty secret must not reach the signer, and the checksum the installer embeds has to be the hash of the signed bytes. |

## P4

| Subsystem | magpie approach | Verdict | hofund approach | Rationale |
| --- | --- | --- | --- | --- |
| Extension bag across protocols | Unknown JSON rides through the large translation path, so a client field can land on a different protocol's object. | Redesign | The provider keeps the extension bag only when the inbound protocol id equals the outbound codec id. Otherwise it drops the bag before encode and again on the decoded response and stream events. Raw unmodeled stream events are dropped on that path after a leading failure has been classified. | A same-protocol passthrough still round-trips fields the IR does not model. A different protocol must not receive them. `metadata.user_id` is one of those fields, and it can carry a device id. |
| Chat stream usage | Streamed Chat calls ask the upstream for usage in the last chunk. | Adopt | The Chat adapter sets `stream_options.include_usage` on every streamed upstream body. The codec does not add that object on a round trip. | Without the flag, many Chat-compatible upstreams omit usage and the ledger records an empty token count. |
| Messages stream shape | The client expects `message_start` usage, `content_block_stop` before a single `message_delta`, and ids prefixed `msg_`. | Adopt | The Messages encoder always writes `message.usage`, prefixes ids with `msg_`, holds every message delta, closes open blocks, then writes one `message_delta` that carries usage, then `message_stop`. | Claude Code rebuilds the turn from that order. A Chat upstream emits the stop reason before `[DONE]` closes the block, so the encoder has to reorder those two events. |
| Responses stream shape | A Responses client rebuilds history from the event list, including the done events and the final output array. | Adopt | The Responses encoder emits `response.output_text.done`, `response.content_part.done`, an `response.output_item.done` item with `id` and `content`, and a terminal response whose `output` is that array. Every event has `sequence_number`. | Codex reconstructs the assistant item from those frames. A created event with an empty `output` is not enough. |
| Disconnect | Restore copies the backed-up file back over the path. | Redesign | When the file still equals exactly what connect wrote, `disconnect` writes the backup bytes back (or deletes a file connect created). Otherwise each key connect wrote is restored to its pre-connect value when the current value is still the one hofund wrote, and removed when it did not exist before. A value the user changed is kept, with a warning. Keys the user added stay. The backup is deleted only after that write is read back and matches. A file that cannot be parsed is left in place, and the error names `hofund agent disconnect <id> --force`. `--force` writes the backup bytes back. A second disconnect, with no backup left, exits 0. Empty parent directories connect created are removed. The home directory and `XDG_CONFIG_HOME` are not removed. | Replacing the whole file drops edits the user made after connect. Deleting every owned key also drops a value that existed before connect. Restoring the backup when nothing else changed keeps the file byte-identical, and the three-way merge keeps a later edit. |
| Token rotation | The process and the wired agents share one settings store, so a new key is visible to the next request. | Adopt the outcome. | `token rotate` still replaces the token file by rename. The gateway re-reads that file on each request and keeps the last token it read when the file is missing or empty. Agents whose files already match the previous token have only their token keys rewritten, without a new backup. When an agent file cannot be updated, the command prints `hofund agent connect <id>`. | The running process used to keep the token it loaded at startup. Re-reading the file is the part of hot reload this release needs. Rewriting token keys leaves every other line alone. |
| CLI | Help text, a checked config path, and a sample config ship with the process. | Adopt | `--help`, `-h`, and `help` print usage for each command. `config check` prints `config ok:` and the path on success, and starts the error with that path on failure. The CLI default path is the same platform path the menu-bar app uses (`HOFUND_CONFIG`, then the platform config directory). `--config` overrides it. `examples/hofund.toml` has `[[providers]]` and `[[routes]]`. `--dry-run` prints `[redacted]` in place of the bearer token. Connect warns when the tool's configured model string has no route. | A sample file and a path in the error are what a first run needs. The two programs were reading different default paths. |
| Auth header | One gateway key, plus the header each client already sends. | Adopt | Every routed request accepts `Authorization: Bearer`, `x-api-key`, `x-goog-api-key`, or a `key` query value. Each presented secret is compared in constant time. `GET /health` does not require a token and its body is `{"status":"ok"}`. | `x-api-key` is the header Messages clients send. Health is for a probe that must not learn the token. |
| Usage table | Rows carry a timestamp and the UI can sum them. | Adopt the readable form. | `hofund usage` prints each row's time in the local timezone (`YYYY-MM-DD HH:MM:SS`) and a totals line with the request count and the summed input and output tokens. | A unix second is hard to read in a terminal. The totals are the sum of the same columns. |
| OpenCode path | The integration uses the home config directory it was given. | Adopt | When `XDG_CONFIG_HOME` is set, OpenCode's files are `$XDG_CONFIG_HOME/opencode`. When it is unset, the path stays `~/.config/opencode` on every platform, which is what the v2 docs describe (checked 2026-10-25). The v2 page does not name `XDG_CONFIG_HOME`. | The variable is the platform config root. Leaving it unset preserves the documented path, including on Windows. |

## Model names, effort, and token counts

Read from yetone/magpie `e57e785` (`internal/gateway/unknown_model.go`,
`internal/gateway/wire_effort.go`, `internal/gateway/effort_update.go`,
`internal/provider/bare.go`, `internal/gateway/count_tokens_test.go`).
`usagealias.go` and `rename.go` are a usage display alias and a provider-id
rename, not the wire model. The wire model is a hofund route field.

Official level lists, checked 2026-10-25:

- Chat and Responses: <https://developers.openai.com/api/docs/guides/reasoning>
  (`none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`).
- Messages: <https://platform.claude.com/docs/en/build-with-claude/effort>
  (`output_config.effort`: `low`, `medium`, `high`, `xhigh`, `max`).
  `thinking.type = disabled` is how a request asks for no thinking, and some
  models reject it.
- Generative Language: <https://ai.google.dev/gemini-api/docs/thinking>
