# Comparison with magpie

hofund is an independent reimplementation. This table records, per subsystem,
what [magpie](https://github.com/yetone/magpie) does, whether hofund adopts
that behavior or redesigns it, and why. It is a design record, not a porting
guide. hofund does not copy magpie source. The MIT notice lives in
`THIRD_PARTY_NOTICES.md`.

"Adopt" means the outward behavior is worth keeping and is reimplemented
against hofund's crates. "Redesign" means the magpie shape is unsound for
this codebase and hofund does something else on purpose.

Update this table in the same change that adds or changes a subsystem.

## P1

| Subsystem | magpie approach | Verdict | hofund approach | Rationale |
| --- | --- | --- | --- | --- |
| Responses codec | One in-memory request shape shared by Chat Completions, Messages, Responses, and Gemini. `parseResponses` / `buildResponses` speak that shape. A Responses turn is split into items (`message`, `function_call`, `function_call_output`, `reasoning`) and merged back into consecutive same-role messages. Sealed reasoning (`encrypted_content`, with id and summary) is stored and written back byte-faithful. Plain reasoning text is replayed only for models that require it. `instructions` is the system prompt. `allowed_tools` filters the tool list. Argument deltas are reconciled with `function_call_arguments.done` so a finished call is not doubled. A failed response or an `error` event is a failure, not a completed reply. Orphaned tool calls get a synthetic output before the upstream sees them (`pairToolItems`). `store` defaults to false. | Adopt | `OpenAiResponses` in `hofund-codec` translates only to `hofund-ir`. Consecutive assistant items merge into one message. Sealed reasoning on a request or a response body is kept on the thinking part and written back as the original item. A stream carries reasoning text; `encrypted_content` on a streamed item is not yet copied onto the IR event. Unsealed reasoning text is encoded as `reasoning_text`; a quirk profile may strip it before encode. `instructions` round-trips as a leading plain system message. `allowed_tools` narrows tools. The done-event arguments extend the streamed prefix instead of appending a second copy. `response.failed` and `error` stay visible to the caller. A `response.failed` frame that arrives before the turn starts, and whose output is empty, stays an unknown event so the provider can treat it as a failure. After `response.created`, the same frame is a stop reason. The Responses adapter, not the codec, repairs orphaned tool outputs and sets `store: false` when the client did not set `store`. | The hub-and-spoke translation, the item split, sealed-reasoning passthrough, and the stream edge cases are the behavior clients already depend on. Web search, namespaces, custom tools, and hosted tool-search stay out of this version; an unknown item is preserved rather than dropped. Synthetic tool outputs and `store: false` are adapter policy, so a codec round trip stays faithful to the IR. |
| Providers | A very large `Provider` struct (endpoints, keys, accounts, quotas, headers, and product flags together) plus per-vendor files under the gateway as well as under `provider`. HTTP is a shared client. Streaming is decoded into the internal event type. | Redesign | A small `Provider` trait: an id and `execute(request) ->` unary response or a pull-based stream of IR events. Two adapters, `openai_compat` (Chat or Responses, configurable base URL and headers) and `anthropic` (Messages). `reqwest` with rustls. Quirk profiles are applied to the IR before encode. Upstream HTTP failures become a typed error (connect, timeout, status, decode) with the status code and a message. A leading stream event named `error` or `response.failed`, or a chat chunk that is only an error object, becomes status 502 before any event is yielded. A stream is a `Stream` the caller polls, so a slow client slows the upstream read. | The god-struct and the vendor branches inside the gateway are the shape this repository exists to avoid. The trait boundary is what the router and the tests can stand on. Protocol differences stay in the codec the adapter holds. |
| Quirks | Real vendor exceptions are encoded as host and model checks scattered through gateway translation (`rejectTemp`, reasoning replay, optional-field retry, per-vendor envelopes). The knowledge is valuable; the location is not. | Redesign | `hofund-quirks` is data: named profiles of rules (`omit temperature`, `omit top_p`, `default max tokens`, `omit unsealed reasoning`, `fold developer into system`). Providers apply a profile by id. Gateway and router never see a profile. | The exceptions are real. Putting them behind a profile id keeps them testable and keeps vendor names out of the gateway and the router. Profiles shipped here are the small set P1 needs, not a catalog of every upstream. |
| Routing and failover | Several strategies (ordered, rotate, least-used, smart, pace) over accounts, plus a fallback list. A failed upstream is not retried once any reply byte has been sent. Connect failures, 408, 429, 5xx, and a large set of body-word heuristics are retryable. A failed candidate rests for a while so the next request does not hammer it. Global counters back some strategies. | Adopt the pre-byte failover rule. Redesign the rest. | `hofund-router` maps a model name to an ordered list of providers. It fails over only while it has not yet yielded a stream event, and only for connect or timeout errors and for a configurable set of HTTP statuses. The default set is 429, 500, 502, 503, and 504. 400 does not fail over. There is no process-global counter and no rest timer in this version. | Ordered failover before the client sees a byte is the property agents need. Quota-aware strategies and the word heuristics need account state this version does not have. A rest timer would be explicit router state later; it is not a global. |
| Gateway server | One `serve` method, thousands of lines, on a server type that also owns sessions, tools, redaction, and vendor-specific rewrites. Routes for Chat, Responses, Messages, and Gemini live beside that logic. | Redesign | `hofund-gateway` is an axum process edge. It authenticates, picks the inbound `Codec` it was given, asks the router, and writes the encoded body or a pull-based SSE body. It does not name vendors. Default bind is `127.0.0.1:3425`. | The request path should be readable as: decode, route, encode. Vendor adjustments stay below the router. Binding to loopback by default matches a local gateway; a configured address may be wider, and authentication still applies. |
| Auth | Loopback clients may omit a key. Other machines need a gateway key, compared in constant time, after an allow-list and a DNS-rebinding check. Many keys, with budgets. | Adopt constant-time compare. Redesign the policy. | One bearer token, created on first run, stored in a file mode `0600` (on Unix), rotated by replacing a temporary file. Every `/v1` request must send it, including from loopback. Comparison is constant time. | A local gateway with a single token is the P1 threat model. Requiring the token on loopback also closes the rebinding hole magpie closes with a hostname check. Multiple keys and budgets are later. |
| Config | A large settings store, rewritten in place by the agent-integration code, with care taken so a crash does not leave a truncated file. | Adopt atomic replace where this version writes. Redesign the schema. | TOML via `toml_edit`, validated into a small struct: listen address, providers, model routes, failover statuses, token file, usage file. `config check` reports the first structural error. This version does not reload a running process and does not rewrite coding-agent configs. | P1 needs a file a human can read and a checker with a clear error. Hot reload and agent config rewriting are separate subsystems; they are recorded here so they are not forgotten and are not left as comments in code. |
| Usage | A JSONL ledger of rich rows (agent, cache, cost, session, effort), with caches and summaries beside it. Gateway calls and client-reported calls share it. | Redesign | SQLite (`rusqlite`, bundled) with one row per gateway request: model, upstream id, input tokens, output tokens, latency, status, time. `hofund usage` prints that table. Cache counters stay on the IR usage object and are not subtracted from input tokens. | The ledger's product surface is much larger than P1. A single table is enough to see where traffic went. Keeping protocol totals intact avoids inventing a billing split. |
| CLI | A large command tree (accounts, groups, serve, usage, plugins, diagnostics) built around the process. | Redesign | `hofund serve`, `hofund config check`, `hofund token show`, `hofund token rotate`, `hofund usage`. The binary parses arguments and calls the daemon. It does not route and it does not encode protocols. | These are the commands that exercise the P1 process. The rest of magpie's CLI belongs to later subsystems. |

## Not in P1

Gemini, routing strategies other than ordered failover, agent config
rewriting, sessions, and the desktop app are not compared here yet. Add a
row when the subsystem is built.
