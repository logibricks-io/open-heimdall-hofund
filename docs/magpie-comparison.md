# Comparison with magpie

hofund is an independent reimplementation. This table records, per subsystem,
what [magpie](https://github.com/yetone/magpie) does, whether hofund adopts
that behavior or redesigns it, and why. It is a design record, not a porting
guide. hofund does not copy magpie source. The MIT notice lives in
`THIRD_PARTY_NOTICES.md`.

"Adopt" means the outward behavior is worth keeping and is reimplemented
against hofund's crates. "Redesign" means the magpie shape is unsound for
this codebase and hofund does something else on purpose.

Update this table in the same change that adds or changes a subsystem.

## P1

| Subsystem | magpie approach | Verdict | hofund approach | Rationale |
| --- | --- | --- | --- | --- |
| Responses codec | One in-memory request shape shared by Chat Completions, Messages, Responses, and Gemini. `parseResponses` / `buildResponses` speak that shape. A Responses turn is split into items (`message`, `function_call`, `function_call_output`, `reasoning`) and merged back into consecutive same-role messages. Sealed reasoning (`encrypted_content`, with id and summary) is stored and written back byte-faithful. Plain reasoning text is replayed only for models that require it. `instructions` is the system prompt. `allowed_tools` filters the tool list. Argument deltas are reconciled with `function_call_arguments.done` so a finished call is not doubled. A failed response or an `error` event is a failure, not a completed reply. Orphaned tool calls get a synthetic output before the upstream sees them (`pairToolItems`). `store` defaults to false. | Adopt | `OpenAiResponses` in `hofund-codec` translates only to `hofund-ir`. Consecutive assistant items merge into one message. Sealed reasoning on a request or a response body is kept on the thinking part and written back as the original item. A stream copies non-empty `encrypted_content` onto the thinking part and the encoder writes that item back. Unsealed reasoning text is encoded as `reasoning_text` on a request; a quirk profile may strip it before encode. A reasoning item handed to a client is one summary and no content (an `rs_` id, summary events on a stream), and a sealed item carrying content parts, another vendor's, is made into that shape with no seal, on translated and relayed replies alike (D-20, reference: `internal/gateway/reasoning_content.go`). `instructions` round-trips as a leading plain system message. `allowed_tools` narrows tools. The done-event arguments extend the streamed prefix instead of appending a second copy. `response.failed` and `error` stay visible to the caller. A 413 or context overflow becomes `response.failed` with code `context_length_exceeded`, so a Responses client can compact instead of reconnecting. The gateway uses the same `hofund_ir::too_long` classifier as routing to answer a Codex stream before its first event, while other clients keep their pre-stream HTTP status. Codex detection follows User-Agent and Originator prefixes plus Claude Code's Codex plugin headers; other stream failures keep their existing frame. A `response.failed` frame that arrives before the turn starts, and whose output is empty, stays an unknown event so the provider can treat it as a failure. After `response.created`, the same frame is a stop reason. The Responses adapter, not the codec, repairs orphaned tool outputs and sets `store: false` when the client did not set `store`. | The hub-and-spoke translation, the item split, sealed-reasoning passthrough, and the stream edge cases are the behavior clients already depend on. `function`, `custom`, `namespace`, `web_search`, and client `tool_search` are accepted. Same-protocol encode writes the original `tools` array back. Crossing protocols flattens a namespace to `namespace__name`, offers a custom tool as a function with one string `input`, offers client `tool_search` as a function, and drops `web_search` and any other type with a warning instead of a 400. An unknown input item is preserved rather than dropped. Synthetic tool outputs and `store: false` are adapter policy, so a codec round trip stays faithful to the IR. |
| Responses continuation history | The gateway keeps input and output items in a caller-scoped in-memory LRU, expands them before translation, and uses upstream deltas on response-keeping hosts with a whole-body retry after refusal (`reference: internal/gateway/prev_response.go:58-431`). | Adopt with explicit state and privacy bounds | `hofund-gateway` owns a `PrevStore` per gateway. It uses shared item values for own-byte accounting, an injectable clock, a 256 MiB cap, six-hour TTL, and a 64 MiB capture cap. Router attempt metadata identifies translations, relays, subscriptions, plugins, and a secret-free provider/key route. Provider code performs the encoded-body delta and one same-member whole retry. Omitted `store` retains hofund's upstream `store: false`, so only explicit `store: true` selects a delta. | The reference behavior avoids repeated image uploads and gives translating routes whole history. Per-gateway state avoids process-global mutability, streaming capture preserves backpressure, and the explicit-store rule prevents hofund from asking an upstream to persist conversations by default. |
| Providers | A very large `Provider` struct (endpoints, keys, accounts, quotas, headers, and product flags together) plus per-vendor files under the gateway as well as under `provider`. HTTP is a shared client. Streaming is decoded into the internal event type. | Redesign | A small `Provider` trait: an id and `execute(request) ->` unary response or a pull-based stream of IR events. Two adapters, `openai_compat` (Chat or Responses, configurable base URL and headers) and `anthropic` (Messages). `reqwest` with rustls. Quirk profiles are applied to the IR before encode. Upstream HTTP failures become a typed error (connect, timeout, transport, interrupted, status, decode) with the status code and a message. A body failure or timeout after a 2xx status is `Interrupted`, distinct from a pre-send `Connect`; same-member retry of that failure requires an idempotent call. A non-2xx body-read failure still returns the original `Status` and `Retry-After`, using empty bytes when the body cannot be read. A leading stream event named `error` or `response.failed`, or a chat chunk that is only an error object, becomes status 502 before any event is yielded. A stream is a `Stream` the caller polls, so a slow client slows the upstream read. | The god-struct and the vendor branches inside the gateway are the shape this repository exists to avoid. The trait boundary is what the router and the tests can stand on. Protocol differences stay in the codec the adapter holds. |
| Plugin HTTP responses | Providers share one HTTP client and read each reply in their own code. | Redesign | The host handle streams a 2xx body chunk by chunk and buffers a non-2xx body, keeping its status and `Retry-After` even when the read breaks. The SDK `wire` module builds Chat, Responses, Messages, and Generative Language calls (and the Messages and Generative Language token counts) on that handle: encode with the codec, send with one retry only when the connection was never established, and decode the events. An encode error is status 400 and sends nothing. | A plugin cannot hold a raw client, so the host owns pooling and limits. Streaming success bodies keeps time to first byte low; buffering error bodies keeps the status error whole. |
| Provider preset fragments | Go literals declare flat endpoint fields and ordered regions; credentials are derived rather than stored on each row. | Adopt with stricter data validation | TOML fragments keep catalog key names, flat wires, aliases, and declared region order, compile to static data, and use catalog-equivalent selection and credential derivation. Unknown keys fail the build, unknown-region errors list valid ids, and `generative` is a hofund extension. There is no `credential` key. | Rows move without rewriting or duplicating endpoint capabilities in a protocol list. Compile-time validation catches migration typos while preserving current endpoint behavior. |
| Quirks | Real vendor exceptions are encoded as host and model checks scattered through gateway translation (`rejectTemp`, reasoning replay, optional-field retry, per-vendor envelopes). Tool-schema fixes splice the encoded request in place (`reference: internal/gateway/deepseek_schema.go`, `kimi_schema.go`, `grok_schema.go`, `oneof_schema.go`). The knowledge is valuable; the location is not. | Redesign | `hofund-quirks` holds named IR profiles and an automatic ordered encoded-request rule list. Endpoint host, preset, protocol, and model selection stays in that crate. Kernel and SDK transports call the same pass after encoding; a span-aware JSON parser edits only targeted keys, strings, and fields while preserving every other byte. A small `RequestState` per provider instance remembers root-union, token-field, and Responses passthrough-member refusals and drives one same-member retry before later requests use the learned shape. Gateway and router never see a profile or vendor predicate. | The exceptions and cache-prefix preservation are real. A shared data-driven pass keeps them testable on both transports and keeps vendor names out of the gateway and router. Typed IR remains the canonical representation; byte splicing is confined to the final vendor-specific encoding step. |
| Routing and failover | Several strategies (ordered, rotate, least-used, smart, pace, weight, free) over accounts, plus a fallback list. A failed upstream is not retried once any reply byte has been sent. Connect failures, 408, 429, 5xx, and a large set of body-word heuristics are retryable. A failed candidate rests for a while so the next request does not hammer it. Global counters back some strategies. A shorter new rest does not overwrite a longer one, except that a vendor-named time replaces a guessed quota or credit rest of the same cause (`reference: internal/gateway/routing.go:1518-1533`). API-key credit refusals climb from 30 minutes to a repeating week and persist their rung; windowed accounts use reset and renewal observations. Single providers and groups wait out busy replies, and generic key rests are probed through model lists (`reference: internal/gateway/routing.go:207-259`, `reference: internal/gateway/rest_store.go:1-177`, `reference: internal/gateway/patience.go:1-174`, `reference: internal/gateway/rest_probe.go:1-247`). | Adopt the pre-byte failover rule, thinking-only refusal handover, core strategy behavior, credit ladders, patience, and recovery probes. Redesign their state ownership. | `hofund-router` maps a model name to an ordered list of providers. It fails over only while it has not yet yielded a stream event, and only for connect, timeout, or interrupted-body errors under `connect_errors` and for a configurable set of HTTP statuses. A successful result also carries an explicit continuation that the gateway may resume after a thinking-only refusal; the gateway owns protocol splicing over canonical events rather than putting wire formats in the router. The default set is 429, 500, 502, 503, and 504. 400 does not fail over. `strategy` provides a stacking registry, panic-safe permutation validation, exact order, per-pool rotation, smooth weighted rounds, stable free-first tiers, allowance-tiered smart routing, decayed least-used and pace ordering, measured-speed ordering with probes, and current-price ordering. `StrategyState` is shared explicitly across snapshots and keys weighted current weights and probe turns by stable member ids; the least-held and affinity charge hooks remain for P0-2c. The daemon supplies live quota, one-hour-decayed usage, 20-minute-decayed TTFT/TPS, and cached catalog prices through the measurement seam. Typed routing names reject unknown values. Per-member and lower-cased per-account weights default to 1. Provider flags, catalog flags, or all-zero prices mark free members. `hofund_router::Cooldowns` keeps explicit rest timers and ladders keyed by `(MemberId, Option<model>)`; the daemon shares that book across router snapshots. Ready member/model pairs follow strategy order, followed by one soonest cooling probe per request. Model-cooling and unserved-model refusals use model-local rate, generic, and credit ladders, and repeated generic failures move to a model ladder when sibling answers reset the member count. Non-positive header hints are absent. Generic failures do not climb during an active generic rest. API-key credit climbs 30 minutes, 2 hours, 8 hours, 24 hours, 3 days, and a repeating week, with flat soon/retry shapes and 35-day named resets. Windowed account credit uses body/header reset, full-window reset, long retry, then five hours, and renewed-window observations lift it. Only the key ladder persists, through daemon-owned atomic `rests.json` writes. Only exhausted passive observations rest, using resets capped at eight days. Failure events, panics, and passive observations keep the rest that ends later, except that a vendor-named quota or credit time replaces a same-cause guess. Direct providers and route pools use an injected monotonic clock and async sleeper for patience (a pool by its route's `patience`, asking ready members before those still within a vendor hint), so the router has no runtime dependency; the gateway holds streaming waits with SSE comments and records 499 on disconnect. The serving daemon owns concurrent model-list recovery probes in a join set and their 30-minute miss guard in the shared cooldown book, starts no loop in one-shot mode, and aborts outstanding probes on shutdown. Kernel adapters opt in explicitly; subscriptions, plugins, hinted rests, and model rests stay excluded. There is no process-global route counter. | Ordered failover before the client sees a byte is the property agents need. Strategy rounds and rest timers are explicit router state keyed by member and optional model, not process globals, and survive replacement of the member instances. Panic-safe ordering fails open without dropping a candidate. Failure events follow the reference's keep-the-later rule, so concurrent failures of different kinds cannot cut a long rest short. Daemon-owned persistence keeps filesystem I/O out of the router and stores only the long-lived key ladder. Daemon-owned measurement adapters keep quota, usage, speed, and price I/O outside the pure strategy core; ledger migration preserves existing usage rows and adds first-content latency only when a stream supplies it. |
| Conversation affinity | Process-global sticks map scope and conversation to the last answerer, with automatic cache-aware modes, strict pinning, sealed-reasoning recovery, and write-behind `affinity.json` (`reference: internal/gateway/affinity.go:1-1080`). | Adopt the behavior; redesign state ownership and protocol boundaries | `hofund-codec` derives scoped session/first-user/subagent keys and turn boundaries. `hofund-router` owns explicit shared `AffinityState`: auto/session/turn/off/strict decisions, cache-write and silent-prompt accounting, 5-minute and 1-hour warmth, strict-only candidates, and broken-reply handling. The runtime shares that state across snapshots and flushes its bounded, atomically replaced `affinity.json` on shutdown. A separate attempt retry-body hook removes foreign seals once and remembers their hashes per conversation and member. | The cache and strict behavior is worth preserving, but process-global routing state is not. Each daemon has an explicit owner, protocol names stay in codec, vendor-specific cache lifetimes are supplied as member metadata, and sealed content is never persisted. C4-C6 return and spreading rules remain behind the ordered-candidate, stick, and routing-name hook. |
| Gateway server | One `serve` method, thousands of lines, on a server type that also owns sessions, tools, redaction, and vendor-specific rewrites. Routes for Chat, Responses, Messages, and Gemini live beside that logic. | Redesign | `hofund-gateway` is an axum process edge. It authenticates, picks the inbound `Codec` it was given, asks the router, and writes the encoded body or a pull-based SSE body. It does not name vendors. Default bind is `127.0.0.1:3425`. | The request path should be readable as: decode, route, encode. Vendor adjustments stay below the router. Binding to loopback by default matches a local gateway; a configured address may be wider, and authentication still applies. |
| Responses WebSocket | Each create is cloned into an HTTP request and sent through the outer gateway handler; the socket holds the last two replies and maps HTTP/SSE results back to events. Matching interrupts cancel a turn, writes use turn and socket contexts separately, and shutdown drains upgraded sockets beside the HTTP drain (`reference: internal/gateway/responses_ws.go:194-427`). | Adopt the replay, history, cancellation, and drain behavior. Redesign the Rust boundaries. | Axum owns the upgrade and sequential turns while the read loop also handles interrupts and disconnects. `gateway` builds the replay request and calls the same full router as the upgrade, including surface fallback. An inbound surface declares exact Responses socket paths through `plugin-api`, and shared wire names live there too, so the kernel vendor-name rule still holds. History and turn cancellation are explicit socket state, SSE parsing is incremental, and a per-server registry signals and waits for upgraded sockets independently of HTTP request tracking. | Replaying rather than duplicating the request path preserves authentication, failover, accounting, and request events. Small socket-local types avoid process-global history. Turn-scoped write checks keep an interrupt from closing the socket, and the explicit registry covers connections the HTTP graceful drain does not own. |
| Codex passthrough refusals | The gateway recognizes an unknown-parameter refusal of Codex's metadata passthrough, removes the named member or whole object, retries, and remembers the refused shape (`reference: internal/gateway/passthrough_refused.go:1-144`). | Adopt with explicit surface and provider state | `hofund-quirks` owns one refusal parser and byte-preserving editor. Routed Responses providers learn refused members in `RequestState`; the inbound Codex surface keeps a separate set per upstream base. Both paths remove a newly refused member from every input item, retry once for that member, and strip it before later turns. Repeated, unrelated, and cross-protocol refusals do not use the rule. | The metadata is client bookkeeping rather than conversation content. One implementation prevents wording and byte-preservation drift, while per-provider and per-surface state avoids process-global learning. |
| Control provider and model reads | The CLI reads provider configuration and model state directly in its own process (`reference: internal/cli/providers_cli.go:189-240`). | Redesign | A daemon-owned, versioned control API supplies typed provider, cached-model, and route-model reads over the same authenticated TCP and local-IPC transports. Dynamic ids are percent-encoded, cached reads do not contact an upstream, readiness includes shared cooldowns, and responses never expose credentials or base URLs. | One runtime owner prevents separate processes from presenting different live views. Typed DTOs and client methods make transport and validation consistent, while read-only cached routes avoid unnecessary upstream traffic. |
| Auth | Loopback clients may omit a key. Other machines need a gateway key, compared in constant time, after an allow-list and a DNS-rebinding check. Many keys, with budgets. | Adopt constant-time compare. Redesign the policy. | One bearer token, created on first run, stored in a file mode `0600` (on Unix), rotated by replacing a temporary file. Every routed request must send it, including from loopback. Generative Language routes also accept `x-goog-api-key` or a `key` query value. Each presented secret is compared in constant time. | A local gateway with a single token is the P1 threat model. Requiring the token on loopback also closes the rebinding hole magpie closes with a hostname check. The extra header is the one the Generative Language client sends when it is given an API key. Multiple keys and budgets are later. |
| Config | A large settings store, rewritten in place by the agent-integration code, with care taken so a crash does not leave a truncated file. | Adopt atomic replace where this version writes. Redesign the schema. | TOML via `toml_edit`, validated into a small struct: listen address, providers, model routes, failover statuses, token file, usage file. `config check` reports the first structural error. This version does not reload a running process. Coding-agent files are rewritten by `hofund-agent`, recorded in the P2 section. | P1 needs a file a human can read and a checker with a clear error. Hot reload and agent config rewriting are separate subsystems; they are recorded here so they are not forgotten and are not left as comments in code. |
| Usage | A JSONL ledger of rich rows (agent, cache, cost, session, effort), with caches and summaries beside it. Gateway calls and client-reported calls share it. | Redesign | SQLite (`rusqlite`, bundled) with one row per gateway request: model, upstream id, input tokens, output tokens, latency, status, time. `hofund usage` prints that table. Cache counters stay on the IR usage object and are not subtracted from input tokens. | The ledger's product surface is much larger than P1. A single table is enough to see where traffic went. Keeping protocol totals intact avoids inventing a billing split. |
| CLI | A large command tree (accounts, groups, serve, usage, plugins, diagnostics) built around the process. | Redesign | `hofund serve`, `hofund config check`, `hofund token show`, `hofund token rotate`, `hofund usage`, plus `hofund agent list`, `hofund agent connect`, `hofund agent disconnect`, and `hofund agent status`. The binary parses arguments and calls the daemon or `hofund-agent`. It does not route and it does not encode protocols. | These are the commands that exercise the local process. The rest of magpie's CLI belongs to later subsystems. |
