## Cross-cutting provider gaps in hofund

The list and probe behavior that closes the two gaps below is planned in [models.md](../plugins/models.md). This inventory stays partial until that code lands.

- No scheduled upstream model listing (magpie: `/models` per protocol, models.dev catalog via the `catalog` field, `noList` presets use static lists; `internal/provider/models.go`, `autolist.go`). Azure is the exception: the `azure` plugin reads the deployment list, then `/openai/v1/models`, verified with mocks only. The gateway does not call it on a schedule (feature-parity row 2.9).
- No connectivity test / probe (magpie: `internal/provider/test.go`, `translated_probe.go`, `test_as.go`).
- No auth-header learning (magpie retries with one header when both are refused: `RetryOneAuth`, `authheader.go`).
- No balance readers (DeepSeek, Kimi, OpenRouter, SiliconFlow, StepFun, Command Code, Ollama Cloud, AiHubMix; `internal/provider/balance.go`) and no plan quota readers (`planquota.go`, `tencent_usage.go`, `volcengine_usage.go`, `sub2api_usage.go`, `cline_usage.go`).
- No Decide (model-choosing endpoint) support (`decide.go`, `decide_group.go`, `decide_wire.go`, `ollama_decide.go`, `omlx_decide.go`, `mlxserve_decide.go`).
- No partner feed (`partners.go`, fetched list; hofund deliberately excludes it, see presets.toml header).
- No web search API fallbacks (Tavily, Brave, Exa, Firecrawl, You.com, SearXNG; `search_api.go`).
- `docs/feature-parity.md` row 2.7 names these 58 presets and links this file. Region rows live inside a preset; they are not a separate 94-entry catalog.

## Protocol-level quirks hofund must replicate

Per vendor (magpie `internal/gateway` unless noted):

- Anthropic betas: drop `anthropic-beta` values a provider refuses by name, Bedrock list (`betas.go`).
- Claude Code 2.1.x fields a relay may refuse: `thinking.display` values other than summarized/omitted (`anthropic_shapes.go`).
- sub2api Messages group refusal: a 4xx `This group does not allow /v1/messages dispatch` means the API serves no model for that key. D-250 asks the custom relay's Chat API at `/v1` only after that refusal, including when a later request finds the primary left out for a guessed rest or a small window. It remembers Messages as unfit for every provider model until restart, does not rest the key for that refusal, charges a Chat answer's rest, drain, and overflow to the primary, and reports provider Test as `unserved` / `Not served for this key` (`crates/kernel/router/src/api_fitness.rs`, `crates/kernel/daemon/src/d250_messages_refused.rs`). General endpoint detection and preset-wide API fallback remain open.
- Address-added relay per-effort ids: D-246 folds a versioned base listed at two or more of `minimal`, `low`, `medium`, `high`, and `xhigh` into one model with those efforts. Exact suffix matching is case-insensitive, a digit is required in the base's last path segment, and singleton or conflicting families stay unchanged. Requests use the exact or nearest member id, with no effort using the bare id when listed or otherwise the level nearest medium and ties upward. The selected id is used on passthrough, translations, Messages token counts, and probes. Messages member selection reads a level only when `thinking.type` is `enabled` or `adaptive`. Disabled, missing, or any other thinking body leaves effort unset even when `output_config.effort` is `high`, so execute and count send the family default and keep both objects. On an enabled or adaptive body, `output_config.effort` beats the budget, and `none` or `minimal` selects low when `minimal` is also listed. Chat `reasoning_effort: none` stays the none level. Model-scoped overload, cooling, vendor-timed quota holds, and region close use that same sent member id on the next execute and count, so one effort's rest does not block a different member. A model scope that names one old id does not grant the family or a sibling. Dispatch and count read the source store on each call, including rows loaded from disk with no list fetch and rows moved by a provider rename, the same rows probes and the folded control list use. When the bare id is not listed, the folded display name drops a trailing or parenthetical effort word from the default member. A qualified `provider/model` lookup returns that upstream's levels and does not add another hop on the same route. Old member ids still resolve, pass a scope that names that exact id, and remain verbatim; source rows are retained for refresh and pick compatibility. Presets and plugin-owned lists do not fold (`crates/kernel/daemon/src/effort_variants.rs`, `crates/kernel/router/src/effort_models.rs`, `crates/kernel/codec/src/anthropic.rs`, deterministic `d246_*` tests; loopback only). Follow-up: forwarded surfaces still send the wire or bare route id, and there is no per-model listed-as alias, so a renamed member or a family id given to another model stays unfolded.
