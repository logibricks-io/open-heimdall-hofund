The only adapters are `claude-code`, `cline`, `codex`, `crush`, `droid`, `gemini-cli`, `goose`, `grok`, `hermes`, `kimi`, `opencode`, `pi`, `qwen`, `vscode`, and `zed`; all fifteen ship as compiled `plugins/agents/<id>/agent.toml` descriptions. `plugins/registry/tests/agent_conformance.rs` replays each unchanged `plugins/agents/<id>/fixtures/all/` golden suite, and `plugins/registry/tests/agent_regressions.rs` checks shipped metadata, errors, detection, byte handling, and lifecycle edge cases. Gemini writes `model.name`. Crush, Hermes, and Pi write the `providers.hofund` entry and no model pick. Droid appends one `customModels` entry per route after the user's entries. Kimi Code writes `[providers.hofund]` and one `[models."hofund/<route>"]` table per route, and a pick writes `default_model`. Goose gets its own `custom_providers/hofund.json` at connect, and a pick makes it the `active_provider`. Grok Build writes one `[model."hofund/<route>"]` table per route, and a pick writes `[models] default` and turns campaigns off. Qwen Code appends one `modelProviders.openai` entry per route after the user's entries; a pick writes `model.name`, `model.baseUrl`, and `security.auth.selectedType`. Cline lists each route as `hofund/<route>` in `models.json`, and a pick writes the whole `openai-compatible` entry in `providers.json` with `lastUsedProvider`. VS Code appends one `customendpoint` group to `chatLanguageModels.json` and a pick writes `chat.defaultModel`. Zed writes the `language_models.openai_compatible.hofund` provider, keeps hofund's key in the OS credential store, and a pick writes `agent.default_model`. OpenCode `models` lists each route with `name` and an empty `variants` object. Claude Code writes the Opus, Sonnet, and Haiku tier env vars and the small-fast model; the Fable env is written only for a Fable id; the subagent model and effort stay unset. Every other id is missing. Verified with mocks only.

## Dynamic and non-config entries (not counted above)

- **omp profiles**: each omp profile appears as an extra agent row (`omp.go`, `nativemodels.go`).
- **WSL twins**: on Windows, every Linux-side agent found inside a WSL distro gets a twin row whose files live in the distro and whose gateway address is the Windows host as seen from WSL (`internal/agent/wsl.go`).
- **agentplug**: external agent plugins add rows at runtime (`internal/agentplug`).
- **UA-only clients** (`agents.go` lines 48-54): magpie, curl, pi-desktop. Recognized by User-Agent for usage attribution only; nothing is written.
- **Picker-only agents** (no gateway route, only the model id is written): cursor, copilot, devin. kirocrew, cindy, lody and alma are app-driven (harness pick, import link, REST API).

## Gateway features some agents require (hofund must provide them too)

- `/v1/models` with per-model `api_types` and `capabilities` (cursor-local, claude-desktop listing).
- Ollama API emulation `/api/version`, `/api/tags`, `/api/show`, `/api/chat` (VS Code Copilot Ollama provider, Visual Studio BYOK) - `internal/gateway/ollama.go`, `ollama_chat.go`.
- `/muse-code/models` on the endpoint host (muse) - `internal/gateway/muse.go`.
- Codex ChatGPT backend path `/backend-api/codex` passthrough plus magpie models (codex joined mode), including the Responses WebSocket on `/backend-api/codex/responses` - `internal/gateway/codex_backend.go`, `internal/gateway/responses_ws.go`. Codex wiring sets `supports_websockets = true` for this socket-local continuation.
- Flat model ids `provider~model` mapped back to `provider/model` (minimax-code) - `provider.FlatID`.
- Per-agent identification by User-Agent or by a named key (`magpie-<agent>`) for agents that send no UA (prime-agent, astrbot, codebuddy, copilot-jetbrains).
- Claude Code subagent and effort keys are still unset. Gemini `model.name` is written. OpenCode still has no catalog modalities, limits, or reasoning variants.
