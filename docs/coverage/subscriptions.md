hofund ships subscription plugins for Codex, Claude, Copilot, Gemini, Devin, Kiro, and Factory (see table rows). The daemon turns each signed-in account into a router member and polls quota where implemented (`crates/kernel/daemon/src/subscriptions.rs`), verified with mocks only. Vertex mints a Google access token from an ADC file at `https://oauth2.googleapis.com/token` (`plugins/providers/google-vertex/src/auth.rs`); that is API auth for feature-parity row 2.4, not a subscription.
Counted by kind: 7 built-in rows (codex, chatgpt-api, claude, copilot, copilot GHE, gemini, antigravity), 11 plugin-served rows (13 retired ids in `internal/provider/migrate.go:284` `retiredBuiltins`, qoder/qoder-cn and workbuddy/workbuddy-ai each folded into one row), 2 plugin-only rows (trae-cn, minimax-code), 11 key-plan rows, 2 generic rows.

Key point: in magpie, 13 of the named subscriptions (grok, cursor, devin, kiro, qoder, qoder-cn, factory, zed, workbuddy, workbuddy-ai, zcode, mimo-app, commandcode-plan) are **no longer served by magpie core**. They run in @magpie-community OpenCode auth plugins (JS, run on Bun). The core keeps only movers and readers. To reach parity, hofund needs either a plugin host or a native port of each plugin (source: github.com/magpie-community/plugins, not reviewed here).

Doc URLs were checked on 2026-10-25 (HTTP 200 unless noted). "not found" means no official doc was located. It is not a guess.

## Subscription options

`[[subscriptions]]` already has `routing`, `at_once`, `stays`, and `options`. Two boolean keys in `[subscriptions.options]` control agent sign-in switching:

- `keep_login` (default false). The agent returns to the first account as soon as that account has room, including under in-order routing. The automatic switch (every five minutes) uses the same rule.
- `switch_only` (default false). Only the agent sign-in moves. Gateway routing stays on the account it already chose, and the sign-in does not follow a spent account back to the first one unless `keep_login` or in-order routing asks it to.

- `daily-warmup-at-times` (optional). A string `"06:00,21:30"` or array of
  `HH:MM` values in the subscription's local timezone. When set on a
  subscription that supports daily warm-up, the daemon sends one minimal
  upstream request at each listed time (within one hour after wake) so a
  rolling allowance window can start early. Omitted or empty disables scheduling
  for that subscription; manual `hofund warmup <subscription>/<account>` still
  runs when the account is signed in.

- `daily-checkin` (optional, default false). When set to `true` on a
  subscription whose plugin declares daily check-in, the daemon presses the
  vendor check-in once per local calendar day for each signed-in account.
  Failures are logged and retried on the next local day; routing is unaffected.
  Manual `hofund checkin <subscription>/<account>` runs one check-in now.

Boolean `discover` (default false) under `[subscriptions.options]` on any subscription row opts the daemon into reading configured agents' own sign-in files and importing accounts that are not already stored. The same reads run on demand with `hofund accounts discover` (list) and `hofund accounts discover --add` (import). `HOFUND_NO_ACCOUNTS=1` disables every discovery read even when `discover = true`. Discovery never writes agent credential files and never prints tokens.

Account discovery is implemented for subscriptions that declare an agent home and keep a readable sign-in on disk:

| subscription | agent home | credential files read |
|---|---|---|
| claude | `CLAUDE_CONFIG_DIR` or `~/.claude` | `.credentials.json`, `.claude.json` |
| codex | `CODEX_HOME` or `~/.codex` | `auth.json` (file mode) |
| devin | `XDG_DATA_HOME` or `~/.local/share/devin` | `credentials.toml` |
| kiro | `KIRO_IDE_CACHE` or `~/.aws/sso/cache` | `kiro-auth-token.json` |
| workbuddy | `HOFUND_CODEBUDDY_EXTENSION_DATA` or `$HOME` plus the per-OS path from agent sign-in (for example `.local/share/CodeBuddyExtension/Data` on Linux) | `Public/auth/workbuddy-desktop.info` and `workbuddy-desktop-ai.info` |

Left out until a plugin declares agent home and readable credentials (not Keychain, encrypted stores, or CLI-only sign-in):

| subscription | reason |
|---|---|
| gemini | no `AgentSignIn` declaration; Code Assist creds live under `~/.gemini` but are not wired yet |
| copilot | editor OAuth is not exposed as a stable agent home file hofund reads |
| antigravity, chatgpt-api | no agent sign-in seam |
| plugin-served (factory, zcode, …) | no native plugin or opaque/encrypted agent stores |
| qoder | native plugin; sign-in via user import only, not agent credential files |
| zed | native browser sign-in and user import; no agent credential files |
| cline | agent connect rewrites provider JSON; subscription tokens are not imported from agent files |
| grok, cursor | declared agent homes with readable `auth.json` / cursor-agent config; discovery and import wired in A-2a |

A subscription plugin may also declare that its own sign-in spends the account. That flag lives on the plugin spec, not in config.

### Claude Code agent sign-in switch and import (D-36)

When hofund writes Claude Code's agent home (`hofund accounts switch`, automatic
`NextLogin`, or `hofund accounts discover --add`), the Claude subscription plugin:

- Waits up to 90 s for cross-process run marks beside the target account's saved
  config directory (usage refresh, warm-up, keep-alive), then fails with no
  writes.
- Takes Claude Code's mkdir refresh locks in order: `.oauth_refresh.lock`, then
  `<realpath(agent home)>.lock` (stale 60 s, wait 20 s, touch every 2 s while
  held). Releases them in reverse order.
- Reads the live credentials only after both refresh locks are held, syncs a
  rotated pair back into the account store when the refresh token changed, and
  writes the outgoing account with compare-and-swap on the refresh token.
- Takes `<realpath(.claude.json)>.lock` (stale 10 s) before rewriting the
  profile file.

Swap import and agent discover import keep an account when hofund already has a
usable sign-in (stored secret, saved account directory, or the live agent home
when it matches the account id) with a different refresh token unless the
import's `expiresAt` is strictly later. The daemon surfaces that as a config
error; the CLI prints the full reason string.

Overage handling and Sonnet-only week scopes depend on Claude quota reading,
which is not implemented yet (`quota()` returns unsupported).

## Priority suggestion

- P1: codex (ChatGPT via Codex backend), claude bridge, copilot (+GHE), gemini Code Assist. These four built-ins are still in magpie core, and the P1 agents use them.
- P2: antigravity (ban risk), chatgpt-api, key-plan quota readers (zhipu/zai, cline, kimi-code, minimax, opencode go, stepfun, volcengine, tencent, sub2api). The readers are cheap HTTP calls on top of the presets that already exist.
- P3: the plugin-served set. Decide first whether to build a plugin host (Bun) or native ports, because magpie itself has moved them out of core.
